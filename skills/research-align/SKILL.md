# 科研对齐：让 AI 和你的研究保持一致

核心主张：**对齐不是靠一次长提示词，是靠一份持续维护的状态文件 + 每次开工的复述握手。** 模型忘性大、爱顺着人说、爱补全空白；对齐的本质是把它从"猜"切换到"读 → 复述 → 核 → 写"。

## 什么时候用

- 用户在做科研：写论文/综述、分析实验、回审稿意见、写基金、准备组会
- 用户抱怨「AI 不懂我的研究」「写偏了」「引用是假的」「别自己发挥」
- 同一个项目要跨多个会话继续（今天写引言，下周改讨论）
- 你要基于用户提供的材料做任何事实性输出

## 对齐的最小单元：`.research/` 三件套

在研究项目根目录维护三个文件（模板在 `assets/`）：

| 文件 | 作用 | 维护规则 |
|---|---|---|
| `brief.md` | 唯一事实源：为什么做、做什么、现在到哪、下一步 | 一页以内；状态变了就更新 |
| `claim-evidence.md` | 主张 → 证据锚点 | 每个事实性断言一行；没锚点不许进正文 |
| `decisions.md` | 已定/未决/放弃的决策 | 决策变了先改这里，再改稿 |

**没有就先建。** 首次使用：读 `assets/research-brief.md`、`assets/claim-evidence.md`、`assets/decisions.md`，按模板提问补全，不要凭空填。用户不想建目录时，退化为项目根目录的单文件 `research-brief.md`。

## 五步对齐流程（每次实质性任务开工前）

1. **读**：`brief.md` + 相关 `claim-evidence.md` 条目。不要凭上一轮对话的记忆直接写。
2. **复述**：用 3–5 句复述——研究问题是什么、方法是什么、当前阶段、本次交付物、范围外的事。再列出「我假设但没确认」的点。
3. **提问**：最多 3 个关键问题。能从文件读到的不要问；问那些错了会导致返工的问题。
4. **确认**：用户确认或修正后才开始产出。用户说「直接写」是跳过讨论，不是跳过复述——复述可以压成两句话，但不能没有。
5. **回写**：任务结束更新 `decisions.md`、`claim-evidence.md`，以及 `brief.md` 的「现在/下一步」。

## 四道闸门

1. **开工闸门**：没有复述和确认，不动笔。
2. **证据闸门**：每个事实性断言要么给锚点（文件+页码/段落/原句，或 DOI），要么标 `[待补证据]`。禁止「研究表明」「据悉」这类无源权威。
3. **术语闸门**：术语表统一；新术语先定义再使用；中英文对照固定，不换同义词。
4. **交付闸门**：跑 `references/alignment-protocol.md` 的验收清单，没过不交付。

## 三条铁律

1. **材料优先**：只依据用户提供的材料 + 可核验来源。参数记忆里的内容只能当「待验证线索」，标 `[待核实]`；缺材料就写 `[MATERIAL GAP]`，**不许脑补**。
2. **不越权**：不改研究问题、不加不存在的实验、不替用户下结论。所有超出材料的推断单独标注（「推测：…」）。
3. **不谄媚**：用户说错就指出；用户坚持错误时保留证据、说明分歧，不顺着改结论。

## 任务配方（按类型走）

| 任务 | 配方要点 | 详见 |
|---|---|---|
| 文献综述 | PRISMA/PICO、检索饱和、证据矩阵 | `references/task-recipes.md` |
| 方法/实验 | 协议先行 + 数据清单 + 参数表 | 同上 |
| 结果/讨论 | 主张-证据对齐 + 局限清单 | 同上 |
| 审稿回复 | 逐条矩阵（意见→回应→改动位置） | 同上 |
| 基金/开题 | 目标-可行性-风险三段 | 同上 |
| 组会/汇报 | 一页一结论 + 人话版 | 同上 |
| 对外科普 | 结论先行 + 术语三件套 + 类比标边界 | 同上、`humanize-writing` 技能 |

## 上下文漂移的四个信号

出现任一，停下来重读 `brief.md` 并重新复述：

- 开始出现「一般来说/通常/普遍认为」的泛泛表述
- 引用变模糊（「有研究表明」「相关文献指出」）
- 忘了约束（字数、期刊格式、数据口径、样本范围）
- 顺着用户改结论，而不是要新证据

## 会话交接

结束前写回四件事：**做了什么、决定了什么、还差什么、下一步**。写进 `decisions.md` 和 `brief.md`，下次开工先读。没有写回，下次就要重新对齐——这是最大的时间浪费。
