# 八类科研任务配方

每类都按「输入 → 流程 → 输出 → 验收 → 常见跑偏」写。所有任务都先过 `alignment-protocol.md` 的开工复述。

---

## 1. 文献综述

**输入**：研究问题、检索式/数据库、纳排标准、已读文献池。

**流程**：

1. 先写协议：检索式、数据库、时间范围、纳排标准（PICO/SPIDER 按领域选）。
2. 检索日志：每个库的检索式、命中数、去重数、纳入数——可复现比结论漂亮重要。
3. 三重筛：标题/摘要 → 全文 → 数据提取。每步留排除理由。
4. 证据矩阵：每篇一行（样本/方法/关键结果/局限/与本研究关系），不要写成散文。
5. 饱和判断：连续两轮检索无新主题、无新关键文献 → 停；停不下来要说清为什么。

**输出**：检索日志 + 证据矩阵 + 综述正文（主题组织，不按论文逐篇罗列）。

**验收**：每段有出处；没有「大量研究表明」；结论区分「文献说」和「我归纳」。

**常见跑偏**：按时间线流水账；把摘要当结论；某篇文献只看了标题就引用。

---

## 2. 引言 / 相关工作

**输入**：研究问题、缺口证据（3–5 条）、本文贡献点。

**流程**：

1. 四段骨架：领域现状 → 已有方法及其局限 → 缺口（可验证的那一句）→ 本文做法与贡献。
2. 每个局限都要有文献锚点；「现有方法不够好」必须说清哪里不够、在什么条件下。
3. 贡献列表 ≤3 条，和结果章一一对应。
4. 不写「随着……的发展」式开场。

**输出**：四段结构 + 贡献列表 + 引用锚点。

**验收**：缺口句能被审稿人检验；贡献与实验对得上；没有未引用的事实断言。

**常见跑偏**：综述写成名词堆；把自己的方法说得比证据强；引用凑数。

---

## 3. 方法章

**输入**：实验协议、参数表、数据清单、代码/脚本路径。

**流程**：

1. 先写「可复现清单」：数据、预处理、模型/工具、参数、评价指标、随机种子、硬件。
2. 每个设计选择后面补一句「为什么这样选」；没有理由的默认设置要标出来。
3. 数学符号先建表，正文只用表里的符号。
4. 与已有方法的差异单独一段，不要混在流程里。

**输出**：方法正文 + 参数表 + 符号表 + 复现清单。

**验收**：同行只看这一章能复现；参数与代码一致；符号无冲突。

**常见跑偏**：把代码注释翻译成段落；漏掉预处理；参数写了但没写为什么。

---

## 4. 结果与讨论

**输入**：结果表/图、统计输出、与基线的对比。

**流程**：

1. 先建「主张-证据」映射：每条结果主张对应哪个图/表/检验。
2. 先报事实再解释：数字 + 条件 + 不确定性；解释另起一段。
3. 讨论按「与文献一致 / 不一致 / 意外发现 / 局限」组织；不一致要给出可能原因。
4. 局限必须具体：哪个结论受什么条件限制，不能写「本研究存在一定局限」。
5. 因果表述降级：没有因果设计就写「相关」「伴随」。

**输出**：结果段落 + 主张-证据表 + 讨论 + 局限清单。

**验收**：每个数字可追溯到图/表/原始数据；没有一个「显著」没有检验；解释与结果画清界限。

**常见跑偏**：拿相关当因果；只报显著不报不显著；讨论重复结果章。

---

## 5. 实验设计与分析计划

**输入**：研究问题、可行资源、预注册/伦理要求（如适用）。

**流程**：

1. 先写分析计划：主分析、次要分析、探索性分析分开。
2. 样本量/功效：说清怎么定的；没做功效分析的，写明这是探索性。
3. 变量表：自变量、因变量、协变量、操作定义、测量方式。
4. 预判问题：缺失值、异常值、多重比较、批效应、数据泄漏。
5. 计划冻结：分析前存一版计划，改动要记录原因。

**输出**：分析计划 + 变量表 + 风险清单 + 时间线。

**验收**：别人能按计划复现分析；探索性分析有明确标签；没有「先看结果再定假设」。

**常见跑偏**：先跑再说；多重比较不校正；把探索性结果写成验证性结论。

---

## 6. 审稿意见回复

**输入**：审稿意见原文、修改稿、diff。

**流程**：

1. 拆条：每条意见编号（R1-1、R2-3），判断类型（事实错误/方法质疑/表达/范围）。
2. 逐条矩阵：意见 → 回应要点 → 改动位置（页码/行号/diff）→ 证据。
3. 三类回应分开：改了（给位置）、没改但解释了（给理由）、做不到（给限制与替代方案）。
4. 礼貌但不卑不亢：先谢再答，不写「我们完全同意」除非真的全改。
5. 回应与正文一致：说了改的地方，正文必须真的改了。

**输出**：逐条回复表 + 修改稿 + 改动清单。

**验收**：每条意见都有回应和位置；没有「已修改」但找不到改动；没有回避核心质疑。

**常见跑偏**：答非所问；用「感谢审稿人宝贵意见」凑字数；暗改不说明。

---

## 7. 基金 / 开题

**输入**：指南要求、评审标准、前期基础、团队与资源。

**流程**：

1. 三段结构：为什么值得做（缺口+意义）→ 怎么做（路线+可行性）→ 能做成什么（产出+指标）。
2. 每个创新点配一个「为什么你能做成」的依据（前期数据/方法积累/合作资源）。
3. 风险表：风险 → 概率 → 影响 → 应对方案（不能只写「风险可控」）。
4. 指标可考核：数量、时间点、验收方式。
5. 与指南逐条对照，避免漏项。

**输出**：本子骨架 + 可行性证据 + 风险表 + 指标表。

**验收**：评审能在 3 分钟内看懂要做什么；每个承诺有依据；没有空话段落。

**常见跑偏**：背景写两页、方法写半页；创新点无法验证；预算与任务不匹配。

---

## 8. 组会 / 答辩汇报

**输入**：本阶段工作、结论、问题、下一步。

**流程**：

1. 一页一结论：每页标题写结论句，不写「研究进展」。
2. 顺序：问题 → 这周做了什么 → 结果（图优先）→ 卡在哪 → 下一步/需要什么帮助。
3. 图讲三件事：看什么、看到什么、说明什么。
4. 准备三个追问的答案：为什么这样做、和别人比如何、下一步怎么验证。
5. 讲稿写进备注，页面只留结论与图。

**输出**：10–12 页骨架 + 每页一句话结论 + 讲稿备注。

**验收**：每页 30 秒能讲完；结论有数据支撑；卡点说清楚而不是藏起来。

**常见跑偏**：把论文段落贴到 PPT；只讲做了什么不讲结论；报喜不报忧。

---

## 9. 对外科普 / 通俗版（与 `humanize-writing` 技能配合）

**输入**：已核验的结论、目标读者、发布渠道。

**流程**：

1. 一句话结论（外行能复述）→ 人话解释 → 具体例子 → 边界与不确定性。
2. 术语三件套：日常词 + 一句话 + 一个例子；一次最多一个新术语。
3. 类比只搭骨架，并标「这只是类比」；不做超出证据的承诺。
4. 结尾不升华；给「如果只记一句话」。

**验收**：外行能复述核心结论；没有把「相关」说成「因果」；类比边界已标。

**常见跑偏**：为了好懂牺牲准确；堆比喻；用「科学家发现」代替出处。
