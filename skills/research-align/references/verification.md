# 引文与事实核验

## 一、三类最常见的幻觉

| 类型 | 表现 | 危害 |
|---|---|---|
| 引用不存在 | 编造标题/作者/年份/DOI，格式很规范 | 审稿一查即穿，学术诚信风险 |
| 引用-主张不匹配 | 文献是真的，但原文没支持这个说法（只是话题相关） | 最隐蔽，读者不会逐篇核对 |
| 数据/结果张冠李戴 | 数字对不上原文，或省略了条件（样本、单位、干预） | 结论被悄悄放大 |

## 二、引用核验五步

1. **元数据核对**：DOI 粘到 `doi.org`；核对标题、作者、年份、期刊/会议。
2. **内容核对**：在原文里找到支持该主张的句子，**摘录原句**（保留英文原文）。
3. **锚点记录**：页码/章节/图号，写进 `claim-evidence.md`。
4. **引文支持关系**用下表四个值。关系判定与[证据台账状态](../assets/claim-evidence.md#状态定义)分别记录，原文支持改后的主张才能把台账条目标成 `已验证`。

| 状态 | 含义 | 处理 |
|---|---|---|
| `ALIGNED` | 原文明确支持该主张 | 可用于正文 |
| `OVERSTATED` | 原文支持一部分，主张说得更强 | 降级措辞或补条件 |
| `NOT_SUPPORTED` | 原文没有支持 | 删掉该引用或改主张 |
| `NOT_FOUND` | 找不到原文/元数据不符 | 草稿标 `[待核实]`，按证据模板处理 |

5. **二手回溯**：综述、新闻、博客里的说法要回溯到一手文献；回溯不到就降级为「据某综述转引」。

## 三、工具清单（按需）

| 工具 | 用途 |
|---|---|
| DOI 元数据接口 `api.crossref.org/works/{doi}` | DOI 元数据权威核对 |
| OpenAlex `api.openalex.org` | 检索、引用关系、作者机构 |
| Semantic Scholar API | 引用图谱、摘要、被引次数 |
| arXiv API | 预印本元数据与版本 |
| Unpaywall | 找合法开放获取全文 |
| Zotero + Better BibTeX | 文献库与导出；导出时以出版方字段为准 |
| 书目导出工具 | 从出版页面或书目索引导出 BibTeX，保留字段来源 |
| 多模型交叉核验 | 仅作线索；模型也会编来源，必须回到原始页面 |

## 四、数据与统计核验

- 单位、样本量、显著性水平、置信区间、效应量是否齐全。
- 正文数字与图表是否一致（n、误差线含义、坐标轴单位）。
- 四舍五入前后是否一致（摘要 3.2% vs 表里 3.24%）。
- 每个「显著」是否都有检验方法和 p 值/区间。
- 相关是否被写成因果；横断面数据是否被写成「导致」。
- 百分比是否给了基数（「提升了 50%」——从多少到多少）。

## 五、核验清单（交付前）

- [ ] 每条引用的 DOI/URL 能打开，元数据与正文一致
- [ ] 每条引用-主张都有原句摘录和状态标注
- [ ] 按上节逐项核统计条件。整份报告的逐数字独立对账见 `longform-report` 的独立复核
- [ ] 二手来源已回溯到一手，回溯不到已降级措辞
- [ ] 待核条目按[证据模板的状态定义](../assets/claim-evidence.md#状态定义)处置
- [ ] 高风险结论（医学/临床/法律/政策）已提示人工复核

## 六、必须停下来问用户的情况

- 找不到原文，或元数据对不上
- 原文结论与用户说法相反
- 用户提供的「事实」本身没有来源
- 结论涉及临床、法律、政策、安全等高风险领域
- 用户要求「先写上，后面再改」时，只在草稿标 `[待核实]`，并列入交接

## 七、和写作流程的接口

核验结果回写 `claim-evidence.md`；`OVERSTATED` / `NOT_SUPPORTED` 的条目在正文里同步改措辞或删除。**不要只在台账里标状态、正文不改**——那是假核验。
