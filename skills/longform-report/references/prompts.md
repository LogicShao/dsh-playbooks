# 五个可直接复制的提示词

每段都按实际用出效果的样子保留，包括那些看起来啰嗦的约束——它们是踩过坑加上的。

---

## 一、调研 agent

一次只派一个主题。同一段提示词换主题，可以并行发 5–7 份。

```
你在为一份中文报告收集事实。只产出事实清单，不写报告正文。

工作目录：<绝对路径>

## 你的主题：<一个具体主题，不要写成「相关研究」>

要回答的问题：
1. ...
2. ...

## 可用材料

本地已有全文（纯文本，可直接 grep/read）：
- <路径>（<论文简称>）

主要靠联网检索。重点找：<论文标题或作者>

## 输出

写到 <路径>/research/<编号>-<主题>.md：

| # | 结论（一句话） | 具体数字或机制 | 出处 | 类型 |
|---|---|---|---|---|

出处写清楚：本地文件给行号，网页给 URL 与原文引文。
表后补一节「## 未找到」，写你要但没查到的问题。

## 纪律

- 不许编造，不许用记忆补数字。每个数字必须能在出处里找到原句。查不到就写「未找到」。
- 明确区分「论文实测」「作者推断」「机构报告」「媒体报道」「社区说法」。
- 只写与主题相关的内容，不要发散到其他主题。
- 完成后回复：文件路径、条数、你认为最值得写进报告的 3 条。
```

**几个关键约束为什么要写：**

- 「只产出事实清单，不写正文」——不写这句，agent 会直接交一段成稿，而且事实和推断混在一起，没法核。
- 「出处写清楚：本地文件给行号」——这是复核能进行下去的前提。
- 「查不到就写未找到」——不写这句，agent 会用记忆填空，而且填得很像真的。
- 「完成后回复：最值得写的 3 条」——你不必读完整份清单就能判断这一路质量如何。

---

## 二、复核 agent

这是整条流水线里最重要的一次派发。写完稿之后，另起一个 agent。

```
你要独立复核一份<报告类型>。职责是核对数字与事实，不是改稿，不是重新调研。

## 对象

<主文件绝对路径>
<编译产物>

<调研清单目录> 下有 N 份事实清单：
- A.md（N 条）
- B.md（N 条）

原始材料在：
<论文全文目录>
<外部论文抽取文本目录>

## 你要做什么

### 一、逐个数字核对
把正文里出现的每一个数字找出来，逐条核对：
1. 在事实清单里能否找到
2. 事实清单标的出处里能否找到原句
3. 中文转述有没有改变原意（尤其是范围、条件、限定语）

### 二、重点核对这几条（最容易被写错）
<列 10–15 条你心里没底的，包括你认为最稳的那几条>

### 三、检查证据分级有没有被执行
<报告声称分开处理的几类，逐条检查是否真做到了>

### 四、检查外文转述
抽查至少 8 处英文原文转中文的地方，确认没有改变原意，尤其是：
- 「仅」「双向」「所有」这类范围词有没有被放大或缩小
- 「丢弃」与「注入」有没有被混用
- 「论文推断」有没有被写成「论文实测」

## 输出

写到 <REVIEW.md>：
| # | 报告中的说法（位置） | 复核值 | 判定 | 证据 |

判定只能是：一致 / 不一致 / 无法复现

必须修改的问题（按严重程度排序，给出原文与建议改法）

## 硬要求
- 不许改正文文件、不许改事实清单
- 临时文件放 <review_tmp/>
- 复现不出就写「无法复现」，不许估
- 完成后回复：不一致条数、必须修改的问题列表、整体判定
```

**为什么必须写「重点核对」清单：** 不给清单，复核 agent 会挑最容易核的条目核，然后给你一个漂亮的一致率。给了清单，它会认真去碰硬的。

**为什么必须写「不许改文件」：** 否则它会一边核一边改，你拿到的是一份被改过的稿子加一句「已修正」，无从判断改得对不对。

---

## 三、定向复审

第一轮复核出结果、你改完之后，不要自己宣布「已修正」。再派一次，只核修订项。

```
你要复核一份报告的修订结果。上一轮复核发现 N 处问题，作者已改。
你只需确认这些修订是否改对、有没有引入新问题。

## 对象
<现稿路径>（页数）
上一轮复核报告：<REVIEW.md>
事实清单与原始材料：<路径>

## 要核的修订项
1. <原文问题 → 现稿写法 → 请对着某出处确认>
2. ...

## 其余要抽查的
- 摘要与正文的条数、数字、术语是否同步
- 是否引入了新的算术错误、前后矛盾或未定义引用

## 输出
写到 <REVIEW2.md>：
| # | 修订项 | 现稿写法 | 判定 | 证据 |
判定：改对 / 仍错 / 部分对 / 引入新问题

## 硬要求
同上一轮：不许改任何文件，临时文件放独立目录。
```

**这一步的命中率不低。** 本项目第二轮仍查出 2 条错误、3 条部分正确、6 处新增问题。典型的新增问题是：改一句的时候把另一处的引用关系改断了，或者新加的参考文献条目 URL 是错的。

## 四、从用户的否决里提取写作规范

用户在改稿过程中说过的话，是最准确的规范来源。整理成文件。

```
把下面这段对话里用户提出的所有否决意见，提取成一份可执行的写作规范。

<贴用户的原话，逐条>

要求：
1. 每条否决对应表格里的一行：用户说的原话 → 沉淀成的规则 → 怎么检查
2. 规则要能机械检查的，写成检索模式（例如禁用字符、标题形态、表头形态）
3. 不能机械检查的，写成一个提问（例如「这段能不能删」）
4. 按「行文 / 硬约束 / 数字 / 版式」分组
5. 文件末尾给一份交稿前自查清单
```

**不要把这条交给 agent 自由发挥。** 规范的每一条都应该能指回用户某一句具体的话。凭空发明的规范会在下一次改稿时和用户的真实偏好打架。

---

## 五、去 AI 味（内容稳定之后再做）

```
按 humanize-writing 的技能，对这份稿子做最后一轮处理。

重点只做三件事，不要改内容、不要改数字：
1. 删掉仍然残留的元话语、套话结尾、强行升华
2. 统计高频句式（尤其「不是 X 而是 Y」「真正的 X 是 Y」「恰恰是」），
   保留承担实际对比的，其余改写
3. 检查段落长度分布，把连续几段等长的改成错落

改完列出：改了哪几句、为什么改、删了什么。
```

**顺序很重要。** 数字还在动的时候不要做这一步，改完数字句式又得重来。

**不要把「改得像人写」理解成加修辞。** 九成工作是删。本项目最后那轮，动手的只有十几句，删掉的全是空转的转折与排比。
