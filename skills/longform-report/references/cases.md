# 两个实例

流水线不是设计出来的，是被这两次事故逼出来的。两个实例都做了匿名处理：**保留失败类型和核对方法，去掉具体研究主题、数据与出处**。要的是可迁移的手法，不是案例本身。

---

## 实例一：十页左右的自建实验报告

自建实验环境，报告主体是自己的实验数据，结论由脚本产出的 JSON 汇总而来。

### 数字复查揪出来的四处

| 报告里写的 | 实际值 | 性质 |
|---|---|---|
| 0.520 | 0.52246 | 抄错第三位 |
| 0.999 | 0.998485 | 四舍五入方向错 |
| 0.949 标注为「准确率」 | 0.949 是 macro-F1，准确率 0.950 | 标签与数值错配 |
| 一个长度数字 | 同一节里三个长度分属不同对象 | 张冠李戴 |

四处全部是**自产自销**时漏掉的。写代码的人顺手把中间产物转成了结论，没有第二个人从原始 JSON 重新取数。换成独立复核，四处立刻暴露。

### 一条被反复推翻的判断

报告早期写的是「模型能识别出具体对象」。复核阶段发现，判别力主要来自四个与目标无关的因素：端口、传输层是 TCP 还是 UDP、握手长度、访问模式模板。四条同时切断之后，六项指标从 0.949 掉到 0.522，随机水平是 0.25。

这个结论推翻了自己的初稿。如果不是复核阶段坚持「每条结论都要能指回原始 JSON 的键路径」，报告会带着一个错误的卖点发出去。

### 沉淀下来的纪律

每个数字写成「文件 + JSON 键路径」，例如 `eval_final_a.json → results.tcp4.lowo_clean.mean_macro_f1`。写不出键路径的数字不许进正文。

## 实例二：七页双栏文献综述（全部公开来源）

没有任何自有实验数据，全部依赖公开文献。这是流水线真正被压满的一次。

### 配置

| 项 | 数量 |
|---|---|
| 调研 agent | 7 路（6 路按主题，1 路查写作规范，1 路查近期事件） |
| 事实条目 | 300 余条 |
| 纳入文献 | 24 条（20 条同行评审 + 4 条机构报告） |
| 正文引用 | 76 处 |
| 正文篇幅 | 约 9,650 汉字，7 页双栏 |

按主题拆分的那 6 路，每一路都对应报告的一个小节。这种「一路一节」的切法让合并几乎不需要返工。

### 第一轮复核

核了 116 条数字量化表述。

| 判定 | 条数 |
|---|---|
| 一致 | 93 |
| 不一致 | 18 |
| 无法复现 | 5 |

整体判定：不通过。

18 条不一致里，绝大多数不是数字抄错，而是**转述时把方向、范围、对象弄错了**。最严重的一条：

> 原文：某个判据 **≤3.4 或 ≥4.6 才放行**
> 初稿：数值**落在 3.4 到 4.6 之间时放行**

方向完全反了。但每个数字都在，肉眼扫过去毫无异常。这条如果发出去，懂行的人一眼就知道作者没读懂原文。

其他几类：

- 把「每天 36 TB」写成「总量 36 TB」
- 把「从连接起始算起」写成「握手之后」
- 把「高度重合」写成「不重合」
- 把主动扫描的覆盖范围写成被动镜像所得

### 第二轮定向复审

改了 25 项之后，另起一个 agent 只核修订项。

| 判定 | 条数 |
|---|---|
| 改对 | 10 |
| 仍错 | 2 |
| 部分对 | 3 |
| 新增问题 | 6 |

整体判定：仍需修改。

**修订本身会引入新问题**，这是第二轮最大的价值。典型的新增问题：

- 改了一句话，把另一处的引用关系改断了
- 新加的两条参考文献，URL 一条 404、一条只写到目录
- 摘要里说「六条预测各自在什么条件下会失效」，但正文只有四条写了显式证伪形式

### 三种错误类型

**转述漂移**（占大头）。数字对，方向/范围/对象错。检查手法：把方向词（超过·低于·之间·仅·双向）单独拎出来，对着原文问「这个条件成立时，结论是成立还是不成立」。

**语义空转**。出现过一句「现场恢复为多区域并存的部署形态」，放在协议识别那一行。语法完整、词汇都认识，但不指向任何事实。检查手法：每句话都要能回答「这句对应哪个可指认的出处」，答不上的整句删掉，不要解释它原本想说什么。

**承诺与执行脱节**。摘要写「每条事实标注证据类型」，正文一次也没标；摘要写「五条预测」，正文已经改成六条。检查手法：把所有「本文……」「以下……」开头的句子列出来，逐条去正文找实现。

## 两次项目的对比

| 项 | 实例一 | 实例二 |
|---|---|---|
| 数据来源 | 自有实验 | 公开文献 |
| 复核重点 | 文件键路径 | 论文行号 |
| 主要错误 | 标签错配、张冠李戴 | 转述漂移、语义空转 |
| 复核轮次 | 1 | 2 |
| 主要收益 | 推翻了自己的核心结论 | 揪出把机制写反的致命错误 |

两种场景的复核手法不同，但底层规则一样：**写结论的人不能同时是核结论的人。**

---

## 如果重来一次，会改什么

1. **更早定术语表。** 同一个东西在不同论文里有三四个叫法，合并阶段花了不少时间统一。
2. **给调研 agent 限定条目上限。** 有一路交了 84 条，其中约一半最后没用上，合并成本超过了它的价值。
3. **第一轮复核就要求覆盖摘要。** 第一轮的 116 条里摘要占比偏低，导致「五条/六条」这个矛盾到第二轮才发现。
4. **把「未找到」也纳入复核。** 复核只核了写进正文的条目，没核那些被判定为「查不到」的是不是真的查不到。有几条后来发现其实有来源，只是关键词没搜对。
