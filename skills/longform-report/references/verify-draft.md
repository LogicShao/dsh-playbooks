# 独立复核与定向复审

## 分工

| 角色 | 做什么 | **不许**做什么 |
|---|---|---|
| Lead（你） | 定结构、合并事实、写正文、最终裁决 | 不许跳过复核直接交付 |
| 调研 agent | 按主题产事实台账 | 不许写正文，不许改主文件 |
| 复核 agent | 对着原始出处核每一个数字 | 不许改正文、台账或原始材料，只出独立报告 |

Lead 另派复核者。参与撰写正文或制作待核台账的人不复核自己的产物。

## 独立复核

复核 agent 的提示词要包含四样东西：待核文件路径、事实台账位置、原始出处位置、**必须覆盖的重点条目清单**。不给清单，它会挑容易的核。

输出固定为这张表：

```markdown
| # | 报告中的说法（位置） | 复核值 | 判定 | 证据 |
|---|---|---|---|---|
| 1 | 摘要中均值 0.420 | 0.425 | 不一致 | 合成数据 `results.json` → results.mean |
```

判定只允许三种：**一致 / 不一致 / 无法复现**。无法复现就写无法复现，不许估。

```
你要独立复核一份<报告类型>。职责是核对数字与事实，不是改稿，不是重新调研。

## 对象

<主文件绝对路径>
<编译产物>

<调研清单目录> 下有 N 份事实清单：
- A.md（N 条）
- B.md（N 条）

原始材料在：
<论文全文目录>
<外部论文抽取文本目录>

## 你要做什么

### 一、逐个数字核对
把正文里出现的每一个数字找出来，逐条核对：
1. 在事实清单里能否找到
2. 事实清单标的出处里能否找到原句
3. 摘要和正文的中文转述有没有改变原意（尤其是范围、条件、限定语）

### 二、重点核对这几条（最容易被写错）
<列 10–15 条你心里没底的，包括你认为最稳的那几条>

### 三、检查证据分级有没有被执行
<报告声称分开处理的几类，逐条检查是否真做到了>

### 四、检查外文转述
抽查至少 8 处英文原文转中文的地方，确认没有改变原意，尤其是：
- 「仅」「双向」「所有」这类范围词有没有被放大或缩小
- 方向相反的动作有没有被混用
- 「论文推断」有没有被写成「论文实测」

## 输出

写到 <REVIEW.md>：
| # | 报告中的说法（位置） | 复核值 | 判定 | 证据 |

判定用本配方独立复核段的三种结果。

必须修改的问题（按严重程度排序，给出原文与建议改法）

## 硬要求
- 不许改正文文件、不许改事实清单
- 临时文件放 <review_tmp/>
- 复现不出就写「无法复现」，不许估
- 完成后回复：不一致条数、必须修改的问题列表、整体判定
```

## 定向复审

第一轮复核出结果、你改完之后，不要自己宣布「已修正」。再派一次，只核修订项。

```
你要复核一份报告的修订结果。上一轮复核发现 N 处问题，作者已改。
你只需确认这些修订是否改对、有没有引入新问题。

## 对象
<现稿路径>（页数）
上一轮复核报告：<REVIEW.md>
事实清单与原始材料：<路径>

## 要核的修订项
1. <原文问题 → 现稿写法 → 请对着某出处确认>
2. ...

## 其余要抽查的
- 摘要与正文的条数、数字、术语是否同步
- 是否引入了新的算术错误、前后矛盾或未定义引用

## 输出
写到 <REVIEW2.md>：
| # | 修订项 | 现稿写法 | 判定 | 证据 |
判定：改对 / 仍错 / 部分对 / 引入新问题

## 硬要求
同上一轮，只写复审报告，临时文件放独立目录，正文、台账和原始材料保持只读。
```

## 复核时重点查什么

**第一类，转述漂移。** 数字抄对了，方向、范围、对象错了。典型例子：原文是「某个判据 ≤3.4 或 ≥4.6 才放行」，转述成「落在 3.4 到 4.6 之间放行」——方向完全反了，但每个数字都还在，肉眼扫过去毫无异常。

检查手法：对着原文逐句问「这个条件成立时，结论是放行还是拦截」。方向词（超过/低于/之间/仅/双向）单独拎出来核。

**第二类，语义空转。** 例如「指标已恢复正常」没有指出指标、比较基线或测量条件。

检查手法：每句话都要能回答「这句对应哪个可指认的出处」。答不上来的整句删掉，不要试图解释它原本想说什么。

**第三类，承诺与执行脱节。** 摘要或方法节承诺了某个做法，正文没做。例如摘要写「每条事实标注类型」，正文一次也没标；摘要写「五条预测」，正文已经改成六条。

检查手法：把稿子里所有「本文……」「以下……」开头的承诺句列出来，逐条去正文找对应实现。摘要与正文的数字、条数、术语必须做一次同步比对。
