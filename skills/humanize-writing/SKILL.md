# 去 AI 味：让文字像人在写

核心主张：**去 AI 味是一次减法，不是加修辞。** 九成工作是删掉模板、换成具体、把结构决定权收回给人，剩下一成才是调语气。

## 什么时候用

- 用户说「去 AI 味」「太像 AI」「像人写的」「大白话」「润色一下」
- 用户丢来一段结构工整、形容词多、却没有具体细节的文字，让你重写
- 用户要模仿某个人的文风
- 你要写公众号、报告、邮件、演讲稿，希望别一眼被看出是 AI 稿
- 自己刚写完的稿子读起来像模板，主动加载本技能自检

## 先分清四类任务

| 任务 | 做法 |
|---|---|
| 改写已有文字 | 快速档：删 → 换 → 补 → 读，一次交稿 + 改动说明 |
| 从零写一篇 | 结构优先：先定大纲（或给出大纲等确认），再写正文 |
| 模仿某人文风 | 先做风格校准，见 `references/style-guide.md` |
| 要发布的成稿 | 深度档：三遍法 + 裁判模型 + 人工核查，见 `references/playbook.md` |

只要诊断时用[只体检不改](references/playbook.md#6-只体检不改自己写得还行但想确认)。已有稿件将正式发布时走上表的深度档。还要分清文体：邮件要短，演讲稿要有气口，说明文要具体，议论文要立场，散文允许留白。**不要用一套模板套所有文体。**

## 流程：删 → 换 → 补 → 读

### 1. 删（回报最高，先做）

删掉下面这些，文章不会断；不删，光换词没用：

- **元话语**：在本节中、正如前面提到的、接下来我们将讨论
- **套话开头**：在当今这个时代、随着……的发展、众所周知
- **套话结尾**：总之/综上所述打头，再把前文复述一遍
- **客套**：希望本文对你有所帮助、让我们一起……
- **免责限定**：没有对应具体争议的「但这并不意味着……」「仍需谨慎解读」
- **强行升华**：段尾拔高到时代、未来、人类命运
- **伪平衡**：任何事都有两面性、具体问题具体分析
- **三连排比、四字成语连用**：只留一个，其余删

### 2. 换（抽象 → 具体）

- 形容词 → 事实：「性能很好」→「P95 延迟 80ms」
- 抽象判断 → 动作或场景：「优化了用户体验」→「登录页少点一次，加载从 3 秒到 0.8 秒」
- 名词化 → 动词：「对流程进行了优化」→「改了流程」
- 被动 → 主动：「问题已被解决」→「这个问题修好了」
- 成语 → 大白话：「事半功倍」→「原来半天的活，现在一小时」
- 无源权威 → 删掉或补出处：「研究表明」→ 具体研究，或直接说自己的判断
- 同义词循环 → 认准一个词反复用（重复是精确，不是词穷）

### 3. 补（注入人味，但别过量）

- **立场**：同意什么、反对什么、哪里不确定。结尾要能回答「作者站哪边」
- **具体细节**：一个真实场景、一个数字、一句原话
- **节奏**：长短句混排，允许一句话成段，允许不完整的句子
- **校准的不确定**：不用「或许」「一定程度上」这种空 hedge，改成「我赌」「九成是」「这事我不确定」
- **一个真比喻**：全篇最多一个，且不许用「想象一下」开头
- **情绪落在具体动作上**：写「我把手机扣在桌上」，不写「内心十分复杂」

### 4. 读（验收）

念一遍，标记读到一半需要重读或临时换词的句子，改完再念。逐项用[交付前清单](references/checklist.md)核对原意、出处和适用的文体要求。

## 三条硬规则

1. **不编事实。** 改不动、缺信息的地方标 `[待补：具体数据/来源]`，不许用「研究表明」糊过去；数据、人名、引语必须回到原文核对。
2. **不丢原意。** 「像人」不等于删论证，关键结论、限定条件、因果关系都要保留。
3. **学术/署名场景先问。** 考试、投稿、正式发表：先确认是否允许 AI 参与、是否需要披露，不替用户绕开学术诚信或平台规则。

## 从零写时的结构优先

AI 的八股主要在结构：泛泛开头 + 三段论述 + 展望未来；段落等长、每段小标题、每节小结。写之前：

1. 自己定大纲（或先给用户看大纲等确认），明确详略重点。
2. 提示词写死：「严格按这个大纲写，不要自己加引言、总结、小标题」。
3. 段落长度刻意不均；能写段落就不列点；只在真步骤、真对照时用列表。
4. 把 AI 当积木：让它「给三个开头方式」「想一个具体例子」，由人来搭。
